# DemonX 2.0.0

DemonX controls a machine that can hurt you and wreck work. Keep a hand near the machine's emergency stop and run a new program in
the air first. This is the first release that is not marked as a test, but read **What has not been tested on real hardware**
below: several things in it have only been checked against the built-in simulator.

## What's new since 2.0.0-test.3

- **DemonX Design** (new, a second program in the same download). Draw or import a design (DXF, SVG), edit it (shapes, text,
  nodes, corner radius, group and join, offsets, arrays, align, layers, copy and paste between tabs), then run it on a laser or
  make CNC toolpaths with tools and post processors. It has its own page on port 8090 and its own sign-in (it can share DemonX's
  PIN). DemonX itself is still only for CNC machines; the laser side lives in Design.
  - **Laser panel** with big Stop, Start, Frame and circle Frame buttons, Start from and Job origin, saved positions, a material
    library, a job monitor, an optional Home Assistant camera and a rotary setup. The **Ruida driver** (CO2 lasers with a Ruida
    controller, on your own network only) is off until you turn it on in `design.env`; power is capped by `DESIGN_RUIDA_MAX_POWER`.
    Close LightBurn first: only one program can talk to the laser.
  - Windows: `Start DemonX Design.bat` in the same folder (the guide `READ ME FIRST.txt` explains it). Raspberry Pi and Linux:
    `design/README.md`.
- **Update notice.** DemonX looks at GitHub's public list of releases when it starts and about once a day, and shows a badge in
  the header when a newer one exists, with its notes (as plain text), **Skip this version** (needs the PIN) and **Settings >
  Updates** (Check now, test or stable releases, turn it off). It is the only thing DemonX sends to the internet by itself.
- **Update now** (**Settings > Updates > Allow Update now on this page**, off until you turn it on; Raspberry Pi and other git
  installs run by PM2 only, not Windows yet). A signed-in browser can install the release on offer and restart DemonX: it
  fetches that one tag from GitHub, checks its version, runs `npm install`, builds the new screen **aside** (so reloading the page
  meanwhile is safe), takes the controller lock and swaps the screen in just before the restart. If a step fails, the previous
  version is put back. It will not start unless the machine is idle (no job, probe, move, held jog or macro, and the spindle and
  coolant off), and while it installs it refuses to start a job, probe, macro or frame.
- **One update for both.** Where DemonX Design is also set up under PM2, Update now and `scripts/update.sh` update it too
  (packages, new screen built aside, restart), after DemonX. **Neither is updated while either is busy** (a job, probe, move or
  jog on the CNC, or a laser job or move in Design). A problem with Design only prints a warning: DemonX is still updated.
  Design is never touched where it is not set up. `bash scripts/update.sh v2.0.0` installs a release.
- For contributors: a "Checks" workflow runs the typecheck, tests and builds for DemonX and Design on every pull request.

Not in this release: a Windows in-place updater and checksums on downloads (the update notice and Update now are the first two
steps of that plan).

## Download

| You have | Get |
|---|---|
| Windows 10 or 11 | **`DemonX-2.0.0-windows-x64.zip`** (below). Extract to `C:\` (it makes `C:\DemonX`; extracting a newer zip over an older one keeps your settings), double-click `Start DemonX.bat`, and `Start DemonX Design.bat` for Design. `READ ME FIRST.txt` explains everything. |
| Raspberry Pi | `docs/RASPBERRY-PI.md` in the source |
| Linux or macOS | `docs/LINUX-MAC.md` in the source |

Try it with no machine: pick **Simulator** in the Connection panel's port list.

**Updating from 2.0.0-test.3:** your settings and PIN are kept. Hard-refresh the browser afterwards (Ctrl+Shift+R). On a Raspberry
Pi that also runs Design, restart Design once (`pm2 restart demonx-design`) before the first combined update, so it can say
whether it is busy.

## What has been tested on real machines

By the project owner:

- **DemonX Design with a Ruida laser** (an OMTech Pronto 45): the driver is working on the real laser.
- **`scripts/update.sh` on a Raspberry Pi** that runs both DemonX and Design under PM2: it ran from the code of this release's
  update changes (the one-command update of both) and both programs were online afterwards. This is the command-line update,
  not the Update now button.
- Everything from 2.0.0-test.1 to 2.0.0-test.3 (see those notes).

## What has not been tested on real hardware

Built and checked against the built-in simulator, fake PM2 and fake GitHub (automated tests and browser checks), but not tried
on a real machine:

- **The Update now button has never been pressed on a real Raspberry Pi or Linux machine**: no real release tag has been
  installed with it. The first run should be done at the machine, supervised, with the machine and the laser idle. Many
  Arduino-style GRBL boards reset when DemonX restarts, so expect to home again afterwards.
- **The refusals while busy** (a job, probe or move on the CNC, or a laser job or move in Design) were checked with stand-in
  programs and tests, not with a real job running when the update was started.
- Swapping the screen folders under a running server was only tried on Linux in a test environment.
- The **Windows package** was built, and checked to contain DemonX and Design, but has not been run on Windows 10 or 11 for this
  release (including the SmartScreen warning on a zip downloaded from the internet).
- **On the Ruida laser itself**, jobs (cut and engrave, with air), jogs, frames and Stop have been run. Not yet: Pause and Resume
  (off unless `DESIGN_RUIDA_PAUSE=1`), the saved-positions moves, the circular frame, multi-pass jobs, a lost connection mid-job, and
  a rotary job. There is no homing or user origin yet (a job starts where the head is). See `design/README.md`.
- Parts of Design that go beyond the Ruida laser on the owner's machine: other Ruida controllers and firmware, **USB (GRBL) and
  FluidNC lasers (the G-code path has not been run on a real laser)**, the rotary setup, CNC toolpaths and post processors on a real
  CNC, and the camera.
- Everything listed as untested in the notes of 2.0.0-test.3 still applies.
- HTTPS: the PIN and the page travel unencrypted on your network. Do not expose DemonX or Design to the internet.
