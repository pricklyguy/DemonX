# DemonX 2.0.2

DemonX controls a machine that can hurt you and wreck work. Keep a hand near the machine's emergency stop and run a new program in
the air first.

**This release changes DemonX Design only.** DemonX (the CNC controller) is the same as 2.0.1.

## What's new since 2.0.1 (DemonX Design)

**The Laser tab, from the first runs on a real laser**

- **Move window** (the *Positions* tab of the top box): the arrow buttons, **Move to** a typed X and Y, and **saved positions**
  you can add, rename, change, sort and delete (for example X 25, Y 25 as the place to put work). They are kept per laser on the
  computer that runs Design, so every computer sees the same ones. A move is a rapid with the laser off, at most 100 mm/s, only
  inside the work area, refused while a job runs, and the Go button asks to be pressed twice.
- **Laser panel** with big **Stop**, **Start**, **Frame** and circle **Frame** buttons (Pause too where the controller allows it),
  *Start from*, the nine-dot **Job origin**, and a **Rotary** switch. No scrolling at 860 pixels tall. A red cross on the grid shows
  where the head is.
- **Circular frame** (Ruida): traces a circle through the corners of the job with the laser off, and is checked against the work
  area first.
- **Monitor tab** in the Laser box: close the monitor card to the tab, pop it out again; **mouse-wheel zoom** (drag to move,
  double-click for the whole job) in the preview and the monitor, and a shorter head trail so it no longer hides the work.
- **Copy and paste between browser tabs** of the same browser, into a different design.
- A reminders switch (Settings, Appearance) for the notes in the Laser panel, tighter layer rows, and Layer 1 black by default.

**Big jobs**

- **Fixed: "The job could not be written. Maximum call stack size exceeded"** on a job with a big fill (the writer failed above
  roughly 120,000 points). A 520,000-point fill is now tested.
- **A fill scan line is one sweep across its gaps**, like LightBurn, instead of a stop and a run-up at every small piece (the
  owner's preview showed spiky overscan stubs and a very slow first engrave). On the owner's 15 MB test drawing, as a test engrave, the job
  has about 40 percent fewer points.
- **Editing no longer freezes the page**: the Laser tab's job is worked out in a worker, a DXF file is read in a worker, and the
  shapes and the job's path are drawn once and reused while you pan, zoom or select. Frame, Start and Send wait while a newer job
  is being worked out.

**Ruida, from the owner's Wireshark captures of LightBurn**

- **Home**, **Z moves** (Z+ / Z− with a step and a speed, Z shown as the change since connecting) and **Auto focus**. **All off
  unless you switch them on**: add `DESIGN_RUIDA_HOME=1` and/or `DESIGN_RUIDA_Z=1` to `design.env` (Z includes Auto focus).
- **Frame from Absolute coordinates and from a User origin** (a saved position you star with ☆ in the Move window), the same
  moves LightBurn sends with the box placed at that start point. **Start is not available in those two modes yet**: no job sent
  that way has been captured, and a job built for the current position would land in the wrong place. Start from the current
  position as before.
- **Rotary setup** (Settings, Rotary setup): chuck or roller, steps per rotation and diameters, kept per laser. **While Rotary is
  on, Frame and Start are refused** (by the server too) until a rotary job has been captured.
- **Pause and Resume** remain off unless `DESIGN_RUIDA_PAUSE=1` (see below).

**For updating**

- `GET /api/busy` on Design (this computer only) says whether a laser job or move is going on. The combined update asks it before it
  restarts anything, and refuses while Design or DemonX is busy.

## Download

| You have | Get |
|---|---|
| Windows 10 or 11 | **`DemonX-2.0.2-windows-x64.zip`** (below, with its `.sha256` checksum file, which Update now needs), or Update now from 2.0.1 if you turned it on. A fresh install: extract to `C:\`, double-click `Start DemonX.bat`, and `Start DemonX Design.bat` for Design. `READ ME FIRST.txt` explains everything. |
| Raspberry Pi | `docs/RASPBERRY-PI.md` in the source; `./scripts/update.sh` updates DemonX, and Design too where it is set up under PM2 |
| Linux or macOS | `docs/LINUX-MAC.md` in the source |

**Updating Design on a Pi or Linux shop computer:** run `./scripts/update.sh` from the top of the repository. Because the older
Design server has no `/api/busy`, the first combined update cannot ask it and will say so and refuse; run `pm2 restart
demonx-design` once, then update again. Your `design.env` and `design/data/` (the laser list, saved positions, rotary settings,
material library, camera setup, Ruida laser addresses) stay where they are; if Design used to run from another folder, copy them
across first. Hard-refresh the browser afterwards (Ctrl+Shift+R).

**On Windows the first real Update now is 2.0.1 to this release**: please be at the PC, with the machine idle. DemonX Design is a
separate window and keeps running the old version until you close it and start it again.

## What has been tested on real machines

By the project owner:

- **DemonX Design with a Ruida laser** (an OMTech Pronto 45): jobs (cut and engrave, with air), jogs, frames and Stop (the same as
  2.0.1), and a first shop run of the Laser tab with the laser power off.
- **Update now on a Raspberry Pi** (a git install run by PM2), and `scripts/update.sh` with DemonX and Design both under PM2.
- Everything from the 2.0.1, 2.0.0 and earlier notes.

## What has not been tested on real hardware

- **Nothing new that moves the laser has been run from DemonX Design on the laser yet:** Move to X and Y and the saved positions,
  the circular frame, **Home**, **Z moves**, **Auto focus** and the frames from an Absolute or User origin. They were written from
  recordings of LightBurn and tried against a simulated controller only. Please try each once watching the machine, the laser
  power off, a hand near Stop.
- **Still unknown, because the recordings do not show it:** what Auto focus does and how long it takes; which way Z+ moves and
  the controller's Z limits (try 0.1 mm first); what the two `89` bytes in LightBurn's Home command mean (they are sent as
  recorded) and the controller's status while it homes; how a job is sent in Absolute coordinates, User origin or Rotary mode.
- **Pause and Resume** have never run from Design on the laser. LightBurn's pause turns the beam off; whether Design's does must
  be watched with the power off before `DESIGN_RUIDA_PAUSE=1` is used with it on.
- **The fill fix and the one-sweep fill** are tested against the simulator and on a large drawing's plan; the real run time of a
  large engrave has not been measured since (the time estimate was tuned to one Pronto 45 from timed runs before this change).
- **The Windows updater has still never run on Windows**, and the Windows package has not been run on Windows 10 or 11 since the
  layout change in 2.0.1 (see the 2.0.1 notes). The combined update of DemonX and Design (`update.sh`) has been run on the owner's
  Raspberry Pi, but that Update now also updated and restarted DemonX Design there was not checked, and the refusals while a job or a
  laser job is running were checked with stand-in programs and tests only.
- The Design update, copy and paste between tabs and the Monitor tab were checked in a real browser against the simulator only.
- HTTPS: the PIN and the page travel unencrypted on your network. Do not expose DemonX or Design to the internet.
