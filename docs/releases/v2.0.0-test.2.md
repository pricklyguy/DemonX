# DemonX 2.0.0-test.2

**Still a test release for volunteers.** DemonX controls a machine that can hurt you and wreck work. Keep a hand near the
machine's emergency stop and run a new program in the air first.

## Read this first: DemonX is now locked down until a PIN is set

Before, a fresh DemonX let anyone on your network control the machine. **Now it starts view-only:** every browser can watch,
but none can control, except the browser on the DemonX computer itself, until a PIN is set.

- **On the DemonX computer:** open DemonX and use the "Set a PIN" bar at the top.
- **From a phone or another computer** (headless Raspberry Pi, or no keyboard on the DemonX computer): the server prints a one-time
  **setup code** in its window (Windows: the black window; Raspberry Pi: `pm2 logs demonx`). Open DemonX on the other device,
  enter the code, and choose a PIN.
- **From a terminal:** `npm run set-pin` (Windows package: `Set PIN.bat`). The Raspberry Pi installer asks for a PIN at the end.
- **Don't want a PIN?** "Run without a PIN" is a deliberate choice: browsers on your home network can then control the machine.
- **Outside your home network is always view-only without the PIN:** public addresses, VPNs such as Tailscale, and anything that
  comes through a proxy or tunnel. Signing in with the PIN lifts that.

**If you already run DemonX without a PIN, updating to this release puts it in this view-only state until you set a PIN.**
If you already have a PIN, nothing changes. Forgot the PIN: run `npm run set-pin` (or `Set PIN.bat`) on the DemonX computer.

## What's new since 2.0.0-test.1

- **Phone button and QR code:** a phone button in the header (and Settings, Access) shows the addresses other devices can use,
  with Copy buttons and a QR code to scan. Tailscale and other VPN addresses are labelled.
- **Safer by default** (above): the setup mode, the setup code, `set-pin`, and the home-network-only rule.
- **Visualizer:** the "tool is outside this view" warning no longer makes the 3D view flicker (it now floats over the view, with a
  Fit all button).
- **Updating a Raspberry Pi or Linux machine** no longer stops on the generated `package-lock.json`.
- **Install guides:** the Raspberry Pi guide now clones the default branch (or a release tag), and describes the PIN step.

## What has been tested on real machines

By the project owner:

- **A small plain-GRBL PCB mill on a Raspberry Pi, from a completely fresh install:** the installer, the PIN question and the
  setup code, setting the first PIN from a PC and checking that a phone stays view-only until it signs in, connecting, and
  homing. The QR code was scanned from a phone, on both the home-network address and the Tailscale address (both asked for the
  PIN). The visualizer warning was checked after homing far off the grid.
- **A Windows laptop, from a completely fresh install of the Windows package:** the setup code shown in the black window, the
  "Set a PIN" bar with its "Run without a PIN" choice (a phone on the home network could control the machine without a PIN, then
  needed the PIN, with the "Remember this device" option, once one was set), the QR code scanned from a phone, then connecting to a
  real machine, homing, jogging, and an air cut. `Set PIN.bat` was run to change a PIN that was already set: a phone that was
  signed in was asked for the new PIN immediately.
- **A large FluidNC router, Home Assistant:** everything listed under 2.0.0-test.1 (probing, autolevel, controller settings, the
  MQTT device and dashboard).

## What has not been tested

- **On Windows:** Windows 10, other USB serial adapters (the common CH340 boards need their driver installed
  first), and the SmartScreen warning on a zip downloaded from the internet.
- A long cutting job on a levelled file on the large router; the Frame button.
- Other GRBL variants (grblHAL, GRBL 0.9, ESP3D boards), machines in inches (`$13`), G20 programs, macOS.
- HTTPS: the PIN and the page travel unencrypted on your network. Do not expose DemonX to the internet.

## Known limits

- One shared PIN, no user accounts. A browser that has not signed in cannot press HOLD or RESET either.
- A tunnel to the DemonX computer (an SSH tunnel, `ngrok tcp`) arrives from the computer itself and looks local, so it skips the
  PIN. If you tunnel or forward to DemonX, set a PIN and keep the tunnel private.
- The Windows package is not a Windows service: the computer has to be signed in.
- Remaining job time is an estimate from lines done, rough in the first minute.
- Autolevel refuses relative mode (G91), inches, R-format arcs, G92/G10/G28/G30 and non-XY planes. Rapid G53 moves (park or
  retract) are allowed.

## Reporting problems

Open an issue on GitHub with: what you did, what you expected, what happened, the controller (GRBL or FluidNC and its version),
your operating system, and the lines from DemonX's Console or the black window. Screenshots help.
